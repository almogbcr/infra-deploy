# Helm

## Overview

Helm is a package manager for Kubernetes that simplifies
application deployment and configuration.

In this project, Helm is used to deploy the same application
across three different environments using a single Helm Chart
with separate values files.

Helm is also used to install the following Kubernetes add-ons:

* Argo CD - Manages application deployments by synchronizing
  the configuration from Git to Kubernetes.

* External Secrets Operator - Synchronizes secrets from
  AWS Secrets Manager into Kubernetes Secrets.

* AWS Load Balancer Controller - Creates and manages AWS Load
  Balancers based on Kubernetes Ingress and Service resources.

## Chart Structure
```
helm/
└── webapp
    ├── Chart.yaml
    ├── helm.md
    ├── values.schema.json
    ├── templates
    │   ├── configmap.yaml
    │   ├── deployment.yaml
    │   ├── externalsecret.yaml
    │   ├── ingress.yaml
    │   ├── networkpolicy.yaml
    │   ├── rbac.yaml
    │   ├── resourcequota.yaml
    │   ├── secretstore.yaml
    │   ├── serviceaccount.yaml
    │   └── service.yaml
    ├── values-dev.yaml
    ├── values-prod.yaml
    ├── values-staging.yaml
    └── values.yaml
```

* Chart.yaml - Contains the chart metadata, such as name and version.
* values.yaml - Contains the default configuration.
* values.schema.json - Requires an image digest in SHA-256 format.
* values-dev.yaml - Development configuration.
* values-staging.yaml - Staging configuration.
* values-prod.yaml - Production configuration.
* templates/ - Contains the Kubernetes resource templates.

## Environment Configuration

### values.yaml - Default Configuration for All Environments

#### Application Configuration

In values.yaml we manage the default configuration for all environments.

All environments use the same Docker Hub repository and application port,
but these values can be overridden if needed.

Images use `app.image.imageRepo@sha256:...` with the IfNotPresent policy.
The image repository and digest are supplied by the Argo CD Application,
not stored as image tags in the environment values files. The schema validates
digest format; it does not prove the image exists or passed tests.

For local rendering, provide a digest explicitly:

```bash
helm template webapp helm/webapp --namespace dev \
  -f helm/webapp/values-dev.yaml \
  --set-string app.image.imageDigest=sha256:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
```

This example digest is only a rendering fixture, not a deployable release.

The default number of replicas is set to 1 and can be overridden
for each environment.

#### Application Availability
##### Rolling Update
To minimize downtime, we use the RollingUpdate strategy with
maxUnavailable set to 0 and maxSurge set to 1.

This allows one additional Pod to be created during an update
without reducing the desired number of available Pods.

##### Readiness Probe

Checks if the Pod is ready to receive traffic.
The check is performed using the /health endpoint on port 5050.

If the probe fails three consecutive times, the Pod is marked as NotReady
and stops receiving traffic through the Service.

##### Liveness Probe

Checks if the application is still running and responding.
The check is performed using the /health endpoint on port 5050.

If the probe fails three consecutive times, Kubernetes restarts the container.

##### Topology Spread Constraints

Used in Production to distribute the application Pods
across different Worker Nodes.

This reduces the risk of losing all application replicas
if a single Worker Node fails.

##### Graceful Shutdown

Before terminating a container, Kubernetes waits 15 seconds
using a preStop hook, allowing the ALB time to stop routing
new requests to the Pod.

The termination grace period is set to 60 seconds,
allowing the application to shut down gracefully.

#### Environment Variables
Environment variables are passed to the Flask application using a ConfigMap.

* APP_ENV - Defines the environment name.
* APP_MESSAGE - Defines the message returned by the application.
* LOG_LEVEL - Defines the application logging level.

These values can be overridden for each environment.

The Deployment's Pod template includes a checksum of the rendered ConfigMap.
A promoted ConfigMap change therefore triggers a rolling update so new Pods
receive the updated environment variables. This does not guarantee a healthy
application or automatically roll back a failed rollout.

#### Ingress Configuration
Ingress is a Kubernetes resource that defines how external HTTP
and HTTPS traffic is routed to Services inside the cluster.

The Ingress class is set to alb because we use the AWS
Load Balancer Controller.

The controller reads the Ingress configuration and creates
an Application Load Balancer in AWS.

The ALB handles incoming traffic and routes it to the application.

The host field is left empty because we use the DNS name
generated by AWS instead of a custom domain name.

The target type is set to ip, allowing the ALB to route traffic
directly to the Pods associated with the Kubernetes Service.

The ALB uses the /health endpoint to check the health
of its registered targets.

The target deregistration delay is set to 30 seconds
to allow existing requests to complete.

ALB Pod Readiness Gates are enabled through Argo CD
to ensure new Pods are healthy in the ALB before
they are considered ready by Kubernetes.

#### TLS Termination Strategy

For this demo, the application uses HTTP.

For HTTPS, we would use a custom domain and an ACM certificate in the same
region as the ALB. TLS would terminate at the ALB, with HTTP redirected to
HTTPS. Traffic from the ALB to the Pods would remain HTTP on port 5050.

This is the planned setup; TLS is not implemented in the demo.

#### External Secrets

We use AWS Secrets Manager to store sensitive information
instead of storing secret values directly in Git or Helm values files.

Kubernetes Secrets use Base64 encoding, which is not encryption.

* SecretStore - Defines how External Secrets Operator
  connects to AWS Secrets Manager.

* ExternalSecret - Defines which secrets to retrieve from
  AWS Secrets Manager and synchronize into a Kubernetes Secret.

The application receives the secret as an environment variable.

The secrets are passed to the Flask container as environment
variables using envFrom and secretRef in the Deployment.

#### AWS Configuration

Defines the AWS region used by External Secrets Operator
to retrieve secrets from AWS Secrets Manager.

The region is defined separately in each environment's values file.

#### Resource Quota

ResourceQuota is used to limit the total CPU and memory
requests and limits within a Kubernetes namespace.

This prevents one environment from consuming more than
its allocated resources.

ResourceQuota is disabled by default and can be enabled
and configured separately for each environment.

#### Network Policy

NetworkPolicy is used to control incoming and outgoing
network traffic for Pods.

In our project, it is used to restrict network access
based on the requirements of each environment.

* enabled - Enables or disables the NetworkPolicy.
* denyEgress - Restricts outgoing traffic according to the policy.
* allowedCidrs - Defines the allowed IP address ranges.

NetworkPolicy is disabled by default and can be enabled
and configured separately for each environment.

### values-dev.yaml - Development Configuration

Development is used for testing new application versions.

* Image digest and configuration revision are selected through a manual promotion PR.
* DEBUG log level for easier troubleshooting.
* Internal ALB for restricted application access.
* Environment-specific secrets, resource quotas and network policies.

### values-staging.yaml - Staging Configuration

Staging is used to validate the application before promoting
it to Production.

* The same image digest and configuration revision are promoted from Development.
* Runs in a separate namespace within the DEV EKS cluster.
* Environment-specific secrets, resource quotas and network policies.

### values-prod.yaml - Production Configuration

Production runs in a dedicated EKS cluster.

* The same image digest and configuration revision are promoted from Staging through a manual promotion PR.
* Two application replicas.
* Topology Spread Constraints for Pod distribution across Worker Nodes.
* INFO log level.
* Internet-facing ALB.
* Higher resource quotas.
* Environment-specific secrets and network policies.
